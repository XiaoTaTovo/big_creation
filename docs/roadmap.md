# 开发路线图

路线图按“先证明关键风险，再扩展功能”组织。日期应由团队结合学校节点补充。

## M0：需求与工具链冻结

交付物：

- USB PD 目标版本和 MVP 消息范围；
- CH32H417 数据手册、参考手册、开发板资料与编译调试流程；
- CC 前端/PHY 候选方案对比；
- 屏幕、触摸和 GUI 框架选择；
- 模块边界、内存预算、核间通信草案；
- 至少一组合法且可重复使用的协议测试向量；
- 风险清单和验收指标初值。

退出条件：所有“必须尽快回答的问题”都有负责人、证据和明确结论，或者记录为带截止日期的阻塞项。

## M1：采集链路原型

交付物：

- 在开发板或实验板上获得稳定的原始记录；
- 时间戳、通道、帧边界和溢出计数可观察；
- PC 端可接收并保存原始数据；
- 在不同界面负载下完成吞吐和丢帧测试；
- 确认监听电路不会明显干扰待测设备协商。

退出条件：对已知输入能重复得到一致记录，并量化吞吐、缓存与丢帧边界。

## M2：协议解析与 PC 回归

交付物：

- Header、控制消息、基础数据消息和 CRC 解析；
- 纯逻辑解析库可在 MCU 与 PC 端编译；
- 正常、异常和未知报文测试向量；
- 解析错误具有明确分类，不因坏帧崩溃；
- 初步协商事件归纳。

退出条件：目标范围内测试用例通过，PC 与 MCU 关键输出一致。

## M3：嵌入式 GUI

交付物：

- 采集状态页；
- 报文时间线与筛选；
- 单帧字段详情；
- 协商摘要和错误统计；
- 暂停、清空、导出等基本操作；
- 在最大预期数据速率下的刷新与内存测试。

退出条件：GUI 不直接访问采集硬件、不阻塞采集路径，且交互指标达到需求文档中的数值。

## M4：硬件集成与稳定性

交付物：

- 原理图、PCB、BOM 和装配说明；
- 电气保护、供电、热和信号完整性检查；
- 长时间运行、反复插拔、异常输入和断电恢复测试；
- 固件升级、版本显示和故障诊断方案；
- 外壳与便携性原型。

退出条件：完成受控设备矩阵测试，关键问题有复现步骤和修复记录。

## M5：成果整理

交付物：

- 演示固件与可复现实验；
- 用户手册、开发文档和测试报告；
- 关键性能对比和成本分析；
- 结题报告、论文/专利所需证据；
- 已知限制和后续规划。

退出条件：任何团队成员按文档都能重现演示和主要测试结果。
