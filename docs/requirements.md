# 产品需求草案

状态：Draft 0.1

## 1. 产品定位

PD Insight 面向 USB PD 学习、嵌入式教学和基础研发调试，目标是在有限成本和体积下，提供比普通功率表更清晰的协议过程展示。

它首先是一台**协议观察与分析工具**，不是工业级一致性认证设备，也不替代高带宽示波器。

## 2. MVP 功能范围

### 必须具备

- 从选定的 CC 通道获取可重复的 USB PD 通信数据；
- 为每条记录提供时间戳和来源/方向信息，无法判断时明确标为未知；
- 识别目标范围内的 SOP 类型和 USB PD 帧边界；
- 解析 Header、Message ID、消息类型、Data Object 数量和 CRC 状态；
- 展示报文时间线、字段详情、错误/警告和关键协商事件；
- 支持暂停、继续、清空、筛选和查看单帧详情；
- 通过一种稳定接口向 PC 导出原始记录和解析结果；
- 暴露采集溢出、解析失败、CRC 错误和资源占用统计。

### MVP 暂不承诺

- USB-IF 一致性认证；
- 高速 USB 2.0/3.x 数据链路分析；
- 示波器级模拟波形显示；
- 主动注入、故障注入或自动化攻击能力；
- 一次性覆盖所有 USB PD 版本、EPR、PPS、Cable/VCONN 场景；
- 与所有品牌充电器和设备完全兼容。

## 3. 典型使用流程

1. 用户连接待测 Source、Sink 和分析设备；
2. 设备完成自检并显示 CC 通道与采集状态；
3. 用户开始采集；
4. 页面实时显示报文和协商摘要；
5. 用户筛选控制/数据消息并查看字段；
6. 用户保存或导出本次会话；
7. 用户使用 PC 工具回放并与嵌入式结果核对。

## 4. 非功能需求

以下指标必须在 M0/M1 阶段给出数值，不能长期保留“实时、稳定、低成本”等模糊描述：

- 支持的 USB PD 规范版本与消息子集；
- 最大连续采集时长；
- 时间戳分辨率与长期漂移；
- 给定报文速率下的允许丢帧率；
- 单次可保存的原始记录和解析帧数量；
- 从采集到屏幕可见的最大延迟；
- GUI 最低可接受帧率和交互响应；
- 设备供电方式、允许的 VBUS/CC 工作范围和保护等级；
- BOM 成本目标、PCB 尺寸和功耗目标；
- 导出带宽、文件/线协议版本和兼容策略。

## 5. MVP 验收原则

- 测试输入必须可复现：优先使用固定二进制测试向量、已知抓包或受控 Source/Sink。
- 对每一种“支持的消息”至少准备正常、截断、CRC 错误和未知字段用例。
- 嵌入式端与 PC 参考解析器对同一输入给出一致的关键字段。
- 开启 GUI 与关闭 GUI 时，采集结果的完整性差异在已定义阈值内。
- 缓冲区满、线缆断开、异常复位等情况不会导致设备失去可恢复性。
- 验收报告同时记录成功用例、失败用例、测试设备、固件版本和原始证据。

## 6. 必须尽快回答的问题

### 协议范围

- 目标 USB PD 版本是什么？是否需要 PD 3.1、PPS、EPR？
- MVP 只解析 SOP，还是包含 SOP'、SOP'' 与 Cable Message？
- 需要展示哪些 PDO/RDO/VDM 字段？
- 是否需要协商状态机，还是仅做逐帧解析和事件摘要？

### 硬件边界

- 采用纯监听、串接透传还是 MCU/PHY 主动参与？
- CC1/CC2 如何保护、选路和避免影响原有协商？
- BMC 恢复由专用 PHY、MCU 外设还是定时器/比较器完成？
- VBUS 是否进入设备；若进入，最大电压、电流和隔离/保护方案是什么？

### 软件与界面

- 使用裸机还是 RTOS？双核分别承担什么任务？
- 屏幕控制器、分辨率、色深、接口和触摸方式是什么？
- 使用 LVGL、厂商库还是自研界面？
- 是否需要中英文、主题、截图、会话保存和搜索？
- 上位机导出使用 UART、USB CDC、USB HID 还是其他接口？

### 验证条件

- 团队已有何种示波器、逻辑分析仪、PD 诱骗器和参考协议分析仪？
- 哪些充电器、线缆、电子负载或开发板可作为固定测试对象？
- 是否能获取一组权威或交叉验证过的 USB PD 报文？
- 论文、专利和结题要求对应哪些可量化技术指标？
