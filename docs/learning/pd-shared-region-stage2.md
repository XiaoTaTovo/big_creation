## 已实现

- 两核 Ld/Link_v3f.ld、Link_v5f.ld 增加 PD_SHARED 区域和占满 32 KB 的 .pd_shared (NOLOAD) 段，共用链接符号 __pd_shared_start/end。
- V3 RAM 长度从 448K-256 改为 448K-256-32K；栈随之下移。V5 原私有数据区不变。加入 bss/栈边界链接断言。
- Common/Common/pd_shared.h 唯一定义布局：32 B 元信息 + 16×48 B 记录 = 800 B。编译期检查记录大小、payload/slots 偏移与总大小。剩余预留空间不作为有效记录使用。
- V3 main 在 IPC 初始化与唤醒 V5 之前调用 PD_Shared_BootInit，只初始化当前 800 B，最后发布 magic。该函数仅供双核共同冷启动；不得在 V5 仍运行时重新调用。
- V5 只读检查 magic、布局版本、总大小、记录大小和容量，显示 SHM OK 或 SHM ERROR。不会清空或修复区域。当前计数继续使用原 IPC MSG 寄存器。
- 两核 main、两份 ld 均保留 before-shared-region-20261106.bak 备份。

当前 PdCaptureRecord 被共享布局引用，布局版本 1 固定其 ABI；未来字段变化必须同步更新布局版本和静态检查，不能仅修改 API 宏。还未实现提交/取出队列、运行期单核重启恢复或完整报文传输。

## 用户验收

1. MRS 依次构建 V3、V5，重新生成 Merge.bin；确认实际下载文件为最新合并产物。
2. 用户手动下载后完整断电重上电，保证两核配套冷启动，不只重启一个核。
3. 屏幕应显示 V3 -> V5、SHM OK、递增 COUNT。观察约 10 秒。
4. SHM ERROR 表示共享布局检查失败，应核对新旧两核是否混用，不继续接入队列。保持 WAITING 则与计数握手分开排查。

此验收只确认 V3 初始化和 V5 跨核读取布局元信息，不证明负载槽并发传输正确。

## 为什么先选 16

16 是容量试验起点，不是协议或芯片要求。16×48=768 B，加元信息共 800 B。2 的幂方便将递增序号用 &15 映射到槽位，但不能因此省略满/空和回绕处理。最终容量应覆盖接收端最长不服务时间内的到达量、突发量和裕量；需要队列高水位、满队列计数和实测服务间隔。如果平均消费速度不足，增加容量只能延迟溢出。

32 KB 预留沿用官方示例，属于保守的原型资源分配，不是 16 个槽必须占用 32 KB；可在验证后缩小分区，但须同时修改两核链接脚本并重做边界验收。
