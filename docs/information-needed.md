# 继续开发前需要团队提供的信息

状态：Open

这份清单用于把申请书中的方向性描述转成可执行工程需求。未知项可以先标记“待定”，但必须指定负责人和最晚确认日期。

## 1. 项目与验收

- 大创项目当前状态：已立项、待答辩、校级/省级或其他；
- 正式起止日期、阶段检查和结题日期；
- 学校要求的硬性成果：实物、论文、专利、软件著作权、报告或竞赛；
- 指导教师对首个演示版本的最低要求；
- 预算实际可用金额、采购与报销限制；
- 仓库可见性：私有还是公开，以及哪些资料不能公开。

## 2. 产品边界

- 设备是纯监听器、串接透传设备，还是主动参与 PD 协商；
- 是否允许报文注入或控制 Source/Sink；
- 目标 USB PD 版本与必须支持的消息；
- 是否纳入 PPS、EPR、SOP'/SOP''、Cable/VDM；
- 需要分析的典型场景：充电器—手机、充电器—诱骗器、开发板或其他；
- 是否必须脱离 PC 独立运行；
- 是否需要保存会话、截图、搜索和导出。

## 3. 现有硬件

请提供清晰照片、型号和资料：

- CH32H417 开发板或计划使用的芯片/板卡版本；
- WCH-Link/调试器型号；
- 显示屏型号、控制器、分辨率、接口、色深和触摸芯片；
- CC/PD 前端器件、参考设计或现有原理图；
- 电源、Type-C 插座、保护器件和 PCB 当前版本；
- 示波器、逻辑分析仪、电子负载、PD 诱骗器和参考协议分析设备；
- 可用于测试的充电器、线缆、手机/笔记本和开发板清单。

## 4. 现有软件环境

- 操作系统版本；
- MounRiver Studio/编译器/SDK/EVT 的准确版本；
- 当前可成功编译和下载的最小工程；
- 是否已选择 RTOS；
- 是否已选择 LVGL，若已选择请给出版本；
- 现有代码、原理图、PCB、BOM、测试记录和抓包文件；
- 团队统一使用的格式化、构建和调试命令；
- GitHub 仓库权限与成员账号。

## 5. GUI 需求

- 屏幕物理尺寸、分辨率和横竖屏方向；
- 必须存在的页面和控件；
- 中文/英文、字体和视觉风格；
- 报文列表最大条数、筛选条件和详情字段；
- 是否显示原始字节、位字段、PDO/RDO 图形和协商状态图；
- 最低刷新率、最大操作延迟和允许的 RAM/Flash 占用；
- 输入方式：触摸、按键、旋钮或无本地输入；
- 异常状态如何提示：丢帧、CRC 错误、断线、缓存满、导出失败。

## 6. 数据接口

采集/解析负责人和界面负责人需要共同确定：

- `CaptureRecord`、`PdFrame`、`PdEvent` 的字段定义；
- 时间戳单位、方向和 CC 通道的表示；
- 原始数据和解析结果由谁拥有、何时释放；
- 队列容量、满队列策略和丢帧统计；
- GUI 获取数据的方式：事件队列、只读快照或分页查询；
- 导出协议和文件格式的版本策略；
- 未知消息、截断帧和 CRC 错误如何表示。

## 7. 团队协作

- 四名成员对硬件、采集、解析、GUI、测试和文档的最终责任边界；
- 每周可投入时间和固定联调时段；
- 谁能批准器件、协议范围和架构变更；
- Issue、分支和 Pull Request 的使用方式；
- 硬件版本与固件提交的对应记录方式；
- 论文/专利材料由谁收集实验数据和维护证据。

## 8. 下一步最小资料包

为了立即开始第一个开发迭代，请至少补齐：

1. CH32H417 板卡准确型号与正反面照片；
2. 屏幕模块准确型号与数据手册；
3. 当前能运行的官方/团队示例工程；
4. 已有原理图或 CC/PD 采集方案；
5. 一组已知输入报文或可复现的 Source/Sink 测试场景；
6. 项目截止日期和首个演示希望实现的页面；
7. 团队对“纯监听还是主动参与”的明确选择。

不要在公开 Issue 或提交中粘贴身份证号、手机号、学号、私人邮箱、访问令牌、SSH 私钥和未脱敏申请书。
